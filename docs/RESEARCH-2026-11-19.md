# Router landscape — compiled research, 2026-11-19

Supersedes the survey table in `ROUTER-LANDSCAPE-2026-11-19.md` where they differ.
Method: GitHub search API metadata, READMEs, vendor docs, and 2026 papers via web
search/fetch. Star counts, benchmark numbers and feature claims are the
sources' own and were NOT reproduced here. Items marked (secondary) rest on a
single third-party article and need verification before anyone acts on them.

## 1. What the research changes

### 1.1 LiteLLM: do not put it in front of our keys without a hard security review
LiteLLM remains the most adopted gateway (core MIT; SSO, guardrails and audit
logs are a commercial enterprise tier). But 2026 has been bad for it:
- Critical proxy advisory GHSA-7hp6-4w63-5g45 (30 Sep 2026, CVSS 9.9):
  privilege escalation to proxy admin from an `internal_user` account, with host
  command execution via MCP stdio.
- CVE-2026-35029: a low-privilege user could reach `/config/update` and modify
  proxy config and environment variables (fixed in 1.83.0).
- A pre-auth SQL injection (CVE-2026-42208, fixed 1.83.7) added to CISA KEV, and
  an MCP command-injection CVE-2026-42271, also KEV-listed (secondary).
- A March 2026 PyPI supply-chain compromise of two releases (secondary), and a
  later report of a compromised 1.107.0 release (secondary, single source).
- Cloud Security Alliance note: the master key is a single point of failure for a
  gateway that centralizes provider keys; Wiz scanned thousands of internet-facing
  gateways.
Our router also centralizes provider keys. Adopting a large, fast-moving control
plane with this record would increase attack surface. Bake-off rule added:
LiteLLM may be evaluated in shadow only, never with production keys, until a
pinned, audited version and network isolation are in place.

### 1.2 Bifrost: promising transport, but the open-source edge is narrower than the marketing
Apache-2.0 Go gateway with a web UI for providers, keys, weights and fallback
chains, config in SQLite or JSON. Adaptive routing (measured weights) is
enterprise-only. One hands-on review (secondary) found fourteen UI pages gated
behind the enterprise license. Fallback chains are weight-ordered and equal
weights have no fixed order. Dashboard auth and virtual keys are enforced when
enabled. Verdict: good reference for the provider/key UI, not a policy engine.

### 1.3 The research literature says our direction is right
- **TwinRouterBench (May 2026):** judges routers on whole-trajectory success. A
  cheap choice at one step can fail later; two rule-based routers failed 38 and
  39 of 40 SWE-bench trajectories despite high static savings; a frontier LLM
  used as router under-predicted hard steps (7 of 147). A trained router did best
  live (75/100 at $25.66 vs 74/100 at $54.73 unrouted; single run). Lessons:
  score end-to-end success, charge cost on failed trajectories, price cache
  loss on mid-trajectory model switches, use execution-verified labels.
- **The Routing Plateau (May 2026):** across 21 routers and 5 benchmarks, nearly
  all reach the same accuracy (top 15 within 0.23 points on RouterBench), and a
  well-tuned kNN is a strong cheap baseline. More data or bigger encoders barely
  help. Progress needs richer inputs than the query, such as signals from a
  preliminary attempt.
Implications for us: (a) stop investing in query-only difficulty classification;
(b) our sticky + tool-outcome + escalation design is the "richer signal" path;
(c) judge changes by cost-per-completed-loop, not per-call accuracy.

### 1.4 Free tiers: more supply, real data-policy risk
- Standing free tiers (Oct 2026 survey of 17 providers): Google Gemini, Mistral,
  Groq, OpenRouter, Z.ai, Cloudflare Workers AI, NVIDIA API Catalog, Cohere;
  others give expiring credits. Cloudflare: 10,000 Neurons/day shared across
  models. OpenRouter `:free`: 20 RPM, 50/day, 1,000/day after a $10 top-up.
- OpenRouter publishes a per-provider data policy. In an Oct 2026 analysis, 9 of
  19 free models ran on hosts that may train on prompts, each a single host with
  no fallback; models rotate out within months. `openrouter/free` picks a free
  model at random filtered by capabilities, and its page says prompts may be
  logged and used to improve models. Turning off "may train" can leave
  requests with no eligible endpoint.
- Known tool-calling gotcha on `:free` endpoints ("no endpoints found that support
  tool use") and free-model tool reliability is the very failure we diagnosed.
Implication: the GUI must show a data-policy badge per provider/model and keep
public-only-free separate from the sensitive wall. This validates our lane design.

### 1.5 Admin-UI patterns worth copying
- **open-model-prism** (archived Apr 2026; ideas only): 4-step setup wizard;
  "Check Connection" probe that says which URL failed; auto model discovery on
  save; per-tenant keys stored as SHA-256 hashes; **Test Route** dry run with a
  step-by-step trace (signals, rule matches, classifier, overrides, chosen model);
  **Synthetic Tests** that generate prompts and score a routing config;
  "Generate Config" client snippets.
- **llmux:** provider enable/disable, key and rate-limit edit, tier, per-provider
  connectivity test and a provider health matrix, strategy switch that applies
  without restart, write-once gateway keys. Its in-memory limit tracking needs
  Redis at scale (we use SQLite).
- **Bifrost:** add provider/keys/weights in a UI or API; zero-config start; UI
  disabled until an admin exists.
- **Portkey:** local gateway console for request logs; richer features hosted-only.

### 1.6 Other findings
- Switchyard (NVIDIA): routes from recent tool activity and outcome signals as the
  agent runs; its docs say to evaluate the full agent against a single-model
  baseline because a cheaper call does not guarantee a cheaper completed task.
  Pre-1.0, library-first, server is a demo.
- FreeLLMAPI (MIT): learns per-(platform, model, key) limits, cools down keys on
  429/5xx, sticky 30 minutes, converts plain-text tool calls to real ones. Its
  own scope statement: personal experimentation only; no privacy wall.
- RouteLLM: strong/weak pair routers trained on Chatbot Arena data; no tool-calling
  support documented; no recent maintenance seen in the repo metadata.
- Archived/avoid: TensorZero (archived), open-model-prism (archived).
- License traps: NadirClaw PolyForm Noncommercial; new-api AGPL; llmgateway.io AGPL.
