# Sovereign Router — review and status, 2026-11-19

## Verdict
Recoverable and healthy; the problem is routing quality on tool turns, not
availability. Live: gateway v0.9.1 / classifier v0.5.0 / nginx on VM103
(Portainer endpoint 8), 98-model registry (md5 bbd17938...), requests succeed.

## Architecture (as built)
sensitivity scan -> classifier (rules, then TF-IDF sidecar when confidence <0.8)
-> sticky check -> `build_candidates` (lanes: private-free, public-only-free,
paid, premium; floors `REQUIRED_QUALITY`) -> cost-ordered failover ->
validation/escalation -> telemetry/ledger. Sort key
`(estimated_cost, -_selection_quality, latency_p50)`.

## What was wrong
1. Tool-turn ranking used a saturated one-shot tooling score (60/85 entries
   scored 5), so free models tied and the fastest weak one won. Fixed: F3 (PR #14).
2. Sticky routing held 89% of Hermes tool turns on the first pick even when
   its tool results kept erroring. Fixed: F2 (PR #14).
3. Telemetry overstated the problem: `has_tool_error` double-counts and
   `repeat_within_60s` flagged tool loops as retries. Fixed in telemetry: this branch.

## What this branch adds (v0.9.3 candidate, undeployed)
F4 per-client model allowlist (opt-in); observe-only per-model tool health
endpoint; repeat-flag fix; docs/failure-log corrections. 776 tests pass
(763 baseline + 13 new).
