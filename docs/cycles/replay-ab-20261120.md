# Offline A/B shape replay: v0.9.1 (main) vs v0.9.3 candidate — 2026-11-20

Harness: `tools/replay/replay_toolloop_ab.py`; profile: `tools/replay/profile-20261120.json`
(aggregates from live `routes.jsonl`, 25,902 rows, no message content).

Method: simulated Hermes-style tool-loop sessions (lengths from the real sticky-run histogram),
fake provider, isolated state, same seeds and registry for both trees, registry restricted to
models the real log observed. A turn's tool result is an error with the real per-model rate of
the model that served the previous turn; `--rho` sets how strongly errors cluster on the same
model within a session. 8 seeds x 400 sessions per cell (~10.7k tool-result turns per tree).
Message text is synthetic: this tests routing feedback dynamics, NOT classifier input.

## Corrections to the first version of this note
1. The first run (150 sessions) was INVALID: unprofiled models got a default error rate and the
   cheapest unprofiled model won nearly every turn, so it measured the default. Fixed by
   restricting to profiled models; results below supersede it.
2. The sandbox needed ~1 s per request because `_encode_len` retried a blocked tokenizer
   download on every call. Real defect (a production container that cannot load the tokenizer
   would pay this on every request): fixed in src/gateway.py (failure cached), test added.

## How strongly do errors cluster in the REAL log?
Lagged conditional error probability on consecutive same-model sticky rows
(`tool_error_next_turn`; lag>=2 is outside the 3-message double-count window):
- Hermes: P(err | prev err) 0.77 (lag 1), 0.62 / 0.61 / 0.57 (lag 2/3/4) vs 0.13-0.24 after a clean turn.
- OpenClaw: 0.52 (lag 1), 0.26 / 0.23 / 0.22 (lag 2/3/4) vs ~0.11.
- n8n: too few pairs to say.
So errors cluster strongly for Hermes (rho ~0.6) and weakly for OpenClaw (rho ~0.25).

## Results (v0.9.1 -> v0.9.3, TOOL_ERROR_BREAK_AFTER = 2)
| rho | error rate | sessions with 3+ consecutive errors | model switches |
|---|---|---|---|
| 0 (independent) | 13.5% -> 14.5% (worse, 0/8 seeds better) | 17 -> 48 | 17 -> 206 |
| 0.25 (OpenClaw-like) | 13.5% -> 15.1% (worse, 0/8) | 48 -> 89 | 14 -> 309 |
| 0.4 | 12.8% -> 14.2% (worse, 0/8) | 88 -> 92 | 11 -> 391 |
| 0.6 (Hermes-like) | 11.2% -> 11.2% (equal) | 143 -> 64 (halved) | 12 -> 412 |
| 0.77 | 8.9% -> 7.0% (better, 8/8) | 143 -> 27 | 16 -> 302 |

With break-after = 3: rho 0.25 -> error rate 13.5% -> 13.6% (parity), 3+ runs 48 -> 46;
rho 0.6 -> 3+ runs 143 -> 143 (no gain). Break-after = 4 at rho 0.25: 13.5% -> 13.3%, no run reduction.

## Reading
- F2 (abandon after 2 consecutive tool errors) does what it was built for where errors cluster
  (Hermes): long error streaks halve at no cost to the overall rate, and it wins clearly if
  clustering is stronger. It is a net LOSS (~+1.5 points) where errors barely cluster
  (OpenClaw-like), because the model it switches to is on average worse than the one it left.
- No single global threshold dominates. v0.9.3 therefore adds an OPT-IN per-client
  `tool_error_break_after` in clients.json (default unchanged = 2). Suggested, pending owner
  decision: hermes 2 (default), openclaw 3. Ship nothing until the exact-attribution ToolHealth
  data from a canary that includes OpenClaw confirms it.
- Limits: assumed one-parameter clustering; per-model rates are the v0.9.1 noisy attribution;
  registry restricted to 20 profiled models and a Hermes-like client policy (OpenClaw also has
  the premium lane, which this does not model).
