# Offline A/B shape replay: v0.9.1 (main) vs v0.9.3 candidate — 2026-11-20

Harness: `tools/replay/replay_toolloop_ab.py`, profile: `tools/replay/profile-20261120.json`
(aggregates from the live `routes.jsonl`, 25,902 rows, no message content).

Method: 150 simulated Hermes-style tool-loop sessions (lengths drawn from the real
sticky-run histogram), fake provider, isolated state, identical seed and identical
registry for both trees. A turn's tool result is an error with probability equal to the
real tool-error rate of the model that served the previous turn. Message text is
synthetic, so this tests routing feedback dynamics, NOT classifier input.

| metric | v0.9.1 | v0.9.3 |
|---|---|---|
| tool-result turns | 470 | 470 |
| tool-error rate | 32.8% | 30.2% |
| sessions with 2+ consecutive errors | 22 | 21 |
| model switches | 19 | 48 |
| turns on models with >=30% real error rate | 432 | 355 |
| non-200 | 0 | 0 |

Reading: the mechanisms act as designed (F2 switches models more, F3 shifts turns off the
flakiest models; zero failures) but the error-rate gain (2.6 points) is within noise at
n=470 (standard error about 2.1 points). This run does NOT demonstrate a large improvement.
Limits: per-model rates are the v0.9.1 next-turn attribution (noisy); models absent from the
profile default to 0.2; one client profile (Hermes); 150 sessions. The harness did not record
3+ consecutive-error runs, the metric F2 should move most; add it and rerun with more
sessions before claiming an effect size. Runtime ~35 min per tree in this sandbox.
