[HEADING_1] Sovereign Router v0.5.3: Architecture, Specification and Implementation Plan

[NORMAL_TEXT] Launch Collective | Owner: Jordan Mason | Drafted 2026-10-31, revision v0.5.3 | Status: PLAN FOR NEXT PHASE. Supersedes v0.5.2: adds the response to the v0.5.2 review (runaway protection, alert-chain heartbeat, premium alert level, provisional targets, streaming and secret-scan corrections, classifier gating, key hygiene). Nothing here is deployed. No secrets in this document.

[HEADING_2] Summary

[NORMAL_TEXT] Build v0.5 as one router for OpenClaw, Hermes and n8n that sends every request to the cheapest model able to do it well, and only pays when the task needs it. v0.5 merges the working pieces of v0.3.3 (free-first ordering, paid fallback, per-model rate limits, complexity routing) and v0.4 alpha (proper source tree, failover rules, privacy lanes), then adds four things the research says matter most: a local difficulty classifier that runs on VM103, output checks that escalate to a stronger model when a cheap answer is unusable, sticky routing inside an agent's tool loop, and a feedback loop that learns from our own traffic.

[NORMAL_TEXT] The largest saving is in catching easy requests. RouterArena (ICLR 2026) found that routers mostly fall short of the ideal because they fail to send easy queries to cheap models. Our v0.3.3 rules have the same problem: any mention of Docker, Proxmox or backups marks a request complex, which describes most Hermes traffic. Fixing that comes first.

[NORMAL_TEXT] Spending is not capped. A request is never refused because of cost; instead the router keeps costs down by choosing cheaper capable models, steering toward cheaper options when a client runs above its daily target, and alerting Jordan when spend is unusual. For a true runaway (a looping agent, a leaked key) the plan adds an emergency paid-lane switch set far above normal spend: when tripped it moves paid traffic to free models rather than refusing it, and Jordan decides whether it is on and at what level.

[NORMAL_TEXT] The cost and free-share targets below are provisional. Phase 0 measures the real free, paid and difficulty-level split, and the targets are reset from that data before Phase 3.

[NORMAL_TEXT] Target: at least 50% lower blended cost per request than production v0.2.1, with no increase in failed agent turns, and under 300 ms of added routing latency for most requests. Production v0.2.1 stays available as the rollback path until Jordan signs off on cutover.

[HEADING_2] Goals, non-goals and success measures

[HEADING_3] Goals

[NORMAL_TEXT] One OpenAI-compatible endpoint for OpenClaw (VM102), Hermes (VM112) and n8n (CT100), each with its own key and policy.

[NORMAL_TEXT] Route on cost and capability per request: free first for easy work, cheapest capable model for hard work, premium only where the client policy allows it.

[NORMAL_TEXT] No spending caps: a request is never refused for budget reasons (Jordan, 2026-10-31). Costs are kept down by routing (free first, then the cheapest capable model), daily cost targets that steer model choice, and alerts.

[NORMAL_TEXT] Keep prompts private: classification runs locally, logs never hold prompt text, and requests containing secrets stay on private lanes.

[NORMAL_TEXT] Every decision explainable from the logs: which model, why, what was skipped, what it cost.

[HEADING_3] Non-goals for v0.5

[NORMAL_TEXT] Training a router model on GPUs (Router-R1 style). VM103 has no GPU and the gain does not justify the hardware.

[NORMAL_TEXT] Multi-call strategies that split one request into several model calls (knnmultiroundrouter, cascades with a judge on every request). They raise cost and latency for agent tool loops.

[NORMAL_TEXT] Image or audio generation, embeddings API for clients, fine-tuning.

[HEADING_3] Lessons that shape v0.5

[NORMAL_TEXT] Agent requests are large. Hermes turns are 12k to 28k tokens, mostly system prompt and tool definitions. Groq free models (8k tokens per minute per model) can never serve them, and the router must skip such models instead of waiting.

[NORMAL_TEXT] Tool definitions say nothing about difficulty. Hermes sends tools on every request, so "has tools" cannot mean "complex".

[NORMAL_TEXT] Keyword rules over-classify. An infrastructure agent mentions infrastructure in almost every request.

[NORMAL_TEXT] Free capacity runs out fast. Seventeen Hermes turns used Ollama's 400k daily token limit in five minutes on 2026-10-31, which caused the 503 incident.

[NORMAL_TEXT] Free providers differ on privacy. The two strongest free OpenRouter models are only offered by providers that train on prompts; they stay off.

[NORMAL_TEXT] Prompt caching changes the price. DeepInfra bills cached input at 20% of the normal rate, so keeping one agent conversation on one model lowers cost.

[NORMAL_TEXT] Startup patches have reached their limit. v0.5 ships as a built image from a source tree with tests.

[HEADING_2] Architecture

[HEADING_3] Request pipeline

[NORMAL_TEXT] Authenticate the client key (sha256 hashes in clients file) and load the client policy: default data class, allowed lanes, premium permission, daily cost target.

[NORMAL_TEXT] Normalize the body: allowlisted fields, max_tokens clamp with a 2048 default, model aliases (auto, cheap, strong, premium, code, long), real model names mapped to aliases per client policy.

[NORMAL_TEXT] Sensitivity scan: known-format detectors for credentials (provider key prefixes, cloud access keys, PEM private key blocks, bearer tokens, password and secret assignments), in the style of gitleaks rules rather than raw entropy. Plain hex hashes, UUIDs, container IDs and commit SHAs are excluded. A match raises the request to data class sensitive, which only providers Jordan has cleared for sensitive data may serve; if none is cleared, the request goes to the private lane with the strongest verified no-retention terms and the event is alerted. The match itself is never logged. Runs log-only in Phase 0 to measure the false-positive rate before it changes routing.

[NORMAL_TEXT] Profile the request: estimated tokens, tools present, images, JSON mode, position in a tool loop, the last user message, and the explicit alias if any.

[NORMAL_TEXT] Classify difficulty into a task class and a level from 1 to 5, with a confidence score (see Difficulty classifier).

[NORMAL_TEXT] Sticky check: if this conversation already has a model and that model is still eligible and within its provider rate limits, reuse it.

[NORMAL_TEXT] Select candidates: policy eligibility, capability, context and per-minute fit, then order by cost among models whose quality for the task class meets the required level.

[NORMAL_TEXT] Cost governor: record estimated tokens and cost before the call against provider rate limits. When a client is above its daily cost target, prefer cheaper models for levels 1 to 3 by lowering the required quality one level. Spending never blocks a request; provider rate limits only move traffic to the next model.

[NORMAL_TEXT] Execute with failover on 401, 403, 408, 413, 429, 5xx, timeouts and connection errors.

[NORMAL_TEXT] Validate the answer and escalate one quality level when it is unusable (see Output validation).

[NORMAL_TEXT] Stream or return the answer with route headers, finalize usage and cost, write the route log line.

[HEADING_3] Difficulty classifier

[NORMAL_TEXT] Three layers, cheapest first. Each layer only runs when the one before it is not confident.

[TABLE]
  ROW: Layer || Method || Cost and speed on VM103 || Decides
  ROW: Rules || Explicit alias, prompt size, images, JSON mode, plus keyword groups that only count together: an infrastructure term raises the level only when combined with a change verb (deploy, migrate, delete, restore, rotate) or a diagnosis verb (debug, fix, why, root cause). || Under 1 ms || Clear cases: explicit alias, greetings and formatting, very long asks, obvious production changes.
  ROW: Embedding nearest-match || A small local embedding model (bge-small or all-MiniLM class, about 30M parameters) embeds the last user message, truncated to 1,500 characters, and compares it with a bank of labeled examples. Majority vote over the closest 7 gives a task class and level with confidence. || About 20 to 50 ms on CPU (to be benchmarked) || Most requests.
  ROW: Local router model || Arch-Router-1.5B (quantized GGUF via llama.cpp) with our routes described in plain English. Input limited to the last user message and route descriptions, about 400 tokens. || Estimated 1 to 3 s on 2 CPUs. In the request path only if the Phase 2 benchmark shows p95 under 1.2 s; otherwise it runs offline after the fact. || Ambiguous requests (in path), or labels and audits for the learning loop (offline).
[/TABLE]
[NORMAL_TEXT] If the classifier sidecar is down or slow (over 1.5 s), the gateway falls back to the rules layer and logs it. Routing never waits on the classifier beyond that limit. When the classifier is uncertain between two levels, it picks the higher one for levels 3 to 5, because under-classifying a hard task costs more in failed work than the price difference.

[NORMAL_TEXT] The example bank starts with about 150 hand-written examples covering typical Hermes and OpenClaw work and grows from production outcomes in phase 4. It stores embeddings and labels, not prompt text.

[HEADING_3] Difficulty levels and routing rules

[TABLE]
  ROW: Level || Meaning || Examples || Required model quality || Typical choice
  ROW: 1 Trivial || Chat, formatting, short lookups || "Say hello", "turn this into a bullet list" || 2 || Free small (Groq gpt-oss-20b) or any free model that fits
  ROW: 2 Routine || Single-step tasks with clear instructions || Summarize a log, status check, read a file and report || 3 || Free large (Groq gpt-oss-120b for small prompts, OpenRouter free for big ones)
  ROW: 3 Moderate || One change or one diagnosis with tools || Restart a container, explain an error, write a short script || 3, prefer 4 if free || Best free model that fits, else cheapest paid
  ROW: 4 Complex || Multi-step work, debugging, planning, code changes || Migrate a stack, find a root cause, refactor || 4 || Cheapest quality-4 model (DeepSeek V4 Flash today)
  ROW: 5 Critical || Production or security changes, architecture, explicit premium || Firewall or credential changes, cutover plans || 5 || Premium lane if the client policy allows it, else the best quality-4 model
[/TABLE]
[NORMAL_TEXT] The client can override with an alias (cheap, strong, premium) or the header X-Sovereign-Level. Overrides are logged.

[HEADING_3] Sticky routing in agent tool loops

[NORMAL_TEXT] An agent turn often spans many requests: the model calls a tool, the agent returns the result, the model continues. Switching models inside that loop wastes the provider's prompt cache and can break tool-call formats. v0.5 keys each conversation by client plus a hash of the first user message and system prompt, keeps the chosen model for 30 minutes of activity, and only switches when that model fails, hits a provider rate limit, or the level of a new user message is higher. The key is a hash; no prompt text is stored.

[HEADING_3] Output validation and escalation

[NORMAL_TEXT] Checks run on non-streamed answers and on the first chunks of streamed ones before the response is committed to the client:

[NORMAL_TEXT] Empty answer with no tool call.

[NORMAL_TEXT] finish_reason "length" with no usable content.

[NORMAL_TEXT] Tool call whose arguments are not valid JSON, or whose function name is not in the request's tool list.

[NORMAL_TEXT] JSON mode requested and the content does not parse.

[NORMAL_TEXT] On failure the router retries once on the next candidate with quality one level higher, logs an escalation, and counts it against the original model's score for that task class.

[NORMAL_TEXT] Streaming: when a streamed answer is a tool call, the router buffers the tool-call chunks until the call is complete (these are short), validates the arguments and only then sends them, so a malformed call can still be escalated. When a streamed answer is text, the router commits at the first content chunk; after that only the empty-answer and length checks can be logged, not escalated. Agents that need every answer validated can request non-streamed responses.

[HEADING_3] Cost governor

[NORMAL_TEXT] Spending is not capped. The governor keeps costs down by steering, and tells Jordan when spend is unusual.

[NORMAL_TEXT] Per provider account: the provider's real rate limits (minute and day request and token windows) stay in the quota store. Reaching one moves traffic to the next model. Each paid provider has a monthly spend alert (DeepInfra $10, Ollama $5 today), which notifies but does not block. This is already live on the v0.3.3 canary as a logged spend_alert event.

[NORMAL_TEXT] Per client: a daily cost target, not a cap. Above the target the router prefers cheaper models for levels 1 to 3, holds level 4 to the cheapest quality-4 model, allows premium only on an explicit request, and sends one alert that day.

[NORMAL_TEXT] Level mix: when level 4 and 5 make up more than 40% of a client's requests in a day, the router alerts, because that usually means the classifier is over-assigning hard levels.

[NORMAL_TEXT] Runaway alarm, hourly: during the first 14 days (no reliable history yet) it fires on fixed thresholds: paid spend over $0.50 in an hour, or a client over 2 times its daily target. After 14 days it fires when an hour exceeds 5 times the trailing 7-day hourly average, with a $1 minimum. It does not stop traffic.

[NORMAL_TEXT] Slow-leak alarms: a projected-month alert when month-to-date spend extrapolates above the sum of the provider alert levels, and a trend alert when daily paid spend rises for 3 days in a row and ends above the client's target.

[NORMAL_TEXT] Emergency paid-lane switch (owner decision, proposed on at $25 per day across all paid lanes, about 8 times today's production spend): when total paid spend for the day crosses it, paid and premium lanes are switched off until Jordan clears it or the day ends, and traffic moves to free models. Requests are still served where a free model fits; large requests that only paid models can serve get 429 with the reason. Jordan can raise, lower or disable it. This is the only mechanism that can limit spending, and it exists for runaways only.

[NORMAL_TEXT] Manual kill switch per client from the admin endpoint, off by default.

[NORMAL_TEXT] Estimated cost is recorded before the call and corrected to actual usage afterwards, including cached-token pricing.

[HEADING_3] Alert delivery and dead-man check

[NORMAL_TEXT] Pull, not push: an n8n workflow polls GET /admin/costs every 15 minutes and sends any new alerts to Signal. The router does not depend on n8n being reachable to keep serving.

[NORMAL_TEXT] Daily all-clear: every day at 08:10 Mountain time the workflow sends a Signal message with the cost summary (spend by client, provider and level, free share, alerts raised). A missing message means the chain is broken, which Jordan can notice without any other tool.

[NORMAL_TEXT] Fallback: if a Signal send fails, the same message goes by email through the registered mailbox connector.

[NORMAL_TEXT] The router records the time of the last poll and reports the alert chain as degraded in /health when no poll has arrived for 30 minutes, so the gap is visible to Portainer health checks and the next poll.

[HEADING_3] Telemetry and learning loop

[NORMAL_TEXT] Each request writes one JSON route line: time, client, level, task class, classifier layer and confidence, chosen model, skipped models with reasons, escalations, latency split (classify, queue, upstream), token usage, cost. Never prompt or response text.

[NORMAL_TEXT] Outcome signals recorded per request: escalation, upstream failure, the same request repeated by the client within 60 seconds (likely retry), and a tool-error result in the next turn of a sticky conversation. A nightly job turns these into per-model, per-task-class quality scores and proposes registry changes for owner approval.

[NORMAL_TEXT] Optional, owner decision: a 2% sample of internal-class requests judged by a strong model for answer quality, expected to cost about $1 per month. The judge sees prompt text, so it is off unless approved.

[HEADING_2] Model registry v2

[NORMAL_TEXT] Extends the v0.3 and v0.4 schema. New fields:

[NORMAL_TEXT] lane: private-free, public-only-free, paid, premium.

[NORMAL_TEXT] quality: a map of task class to score 1 to 5 (chat, infra, code, reasoning, long-context), seeded by hand and updated from outcomes after approval.

[NORMAL_TEXT] cached_input_usd_per_million and latency_p50_ms.

[NORMAL_TEXT] spend_alert_usd: monthly alert level for paid entries (replaces the blocking monthly cap).

[NORMAL_TEXT] extra_body: provider-specific fields such as OpenRouter's data_collection=deny.

[NORMAL_TEXT] probe: a small test request run weekly; failure marks the entry candidate until re-verified.

[HEADING_2] Deployment

[NORMAL_TEXT] One Portainer stack on VM103 with two containers on an internal network: the gateway, and a classifier sidecar running llama.cpp server with Arch-Router-1.5B (Q8 GGUF, about 1.7 GB) and the small embedding model. Sidecar limits: 3 GB memory, 2 CPUs.

[NORMAL_TEXT] LAN port 6075 behind nginx, allowing only VM102, VM112 and CT100. The gateway itself binds to the internal network.

[NORMAL_TEXT] Gateway image sovereign-router:v0.5.x built from a source tree with tests, pushed to the local registry on CT100 (192.168.0.28). No startup patches.

[NORMAL_TEXT] Keys per environment: the canary and v0.5 get their own provider keys instead of copies of production keys, with provider-side spend limits set high where a provider offers them (OpenRouter keys support a credit limit). Production keys stay only in production.

[HEADING_2] Testing and acceptance criteria

[NORMAL_TEXT] Auth, validation and lane-permission matrix tested live.

[NORMAL_TEXT] Failover against a real second provider for 429, 5xx and timeout; provider rate limits never exceeded under concurrent load; no request refused for budget reasons; spend and runaway alerts reach Signal.

[NORMAL_TEXT] Escalation path proven with a model forced to return empty or malformed tool calls.

[NORMAL_TEXT] Sticky routing keeps one model across a 10-step tool loop and switches when that model is rate-limited or failing.

[NORMAL_TEXT] No prompt or response text in any log, ledger or database (grep check on state directory and container logs).

[NORMAL_TEXT] Real OpenClaw, Hermes and n8n traffic through the canary; 7-day soak meets the success measures.

[HEADING_2] Risks and mitigations

[TABLE]
  ROW: Risk || Mitigation
  ROW: Classifier sends a hard task to a weak model || Output checks with escalation, conservative thresholds, client override header, quality scores updated from outcomes
  ROW: Free models disappear or change terms || verified_until expiry, weekly probe job, data_collection=deny on OpenRouter, paid fallback always configured
  ROW: Classifier adds latency or fails || 1.5 s limit with fallback to rules; sidecar health in /health
  ROW: Spending surprises (no caps by design) || Cost-first routing, per-client daily targets that steer to cheaper models, per-provider and premium spend alerts, hourly runaway alarm with fixed thresholds in the first 14 days, projected-month and trend alerts, optional emergency paid-lane switch, manual kill switch
  ROW: Alerts fail silently || Pull-based polling, daily all-clear message, email fallback, degraded alert chain shown in /health
  ROW: Classifier over-assigns hard levels and spend rises || Level-mix alert at 40% level 4 and 5, level 4 held to the cheapest quality-4 model above target, premium only on explicit request above target
  ROW: Classifier under-assigns hard levels and quality drops || Ties go to the higher level for levels 3 to 5, under-classification measured in Phase 2 and sampled in production, output-check escalation
  ROW: Secret scan reroutes normal infrastructure text || Known-format detectors, hashes and IDs excluded, log-only trial in Phase 0 before it affects routing
  ROW: Secrets sent to a provider that keeps data || Sensitivity scan forces private lanes; nothing cleared for sensitive on free public lanes
  ROW: Key exposure || Keys only in mode-600 files; separate keys per environment; rotation by overwriting the file and restarting; Groq and Ollama rotation scheduled in Phase 0
[/TABLE]
[HEADING_2] Rollback

[NORMAL_TEXT] Phase 0: restore the previous registry and patch file from /appdata backups and redeploy the previous stack 12 compose.

[NORMAL_TEXT] Phases 1 to 3: point the client back at v0.3.3 (Hermes) or v0.2.1 (OpenClaw) by changing its base URL and key; delete or stop the v0.5 stack.

[NORMAL_TEXT] Phase 5: switch the production endpoint back to v0.2.1, which stays deployed for 30 days.

[NORMAL_TEXT] VM level: Proxmox snapshot of VM103 before each phase deployment.
